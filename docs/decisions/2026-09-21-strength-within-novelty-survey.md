# 2026-09-21 サーベイ: 新規性を保ったまま既存研究から強さを引き出す

前提: 駒トークン 40・会議ループ・駒ごとの価値分解 (V_i, α_i)・内面 (感情/絆/性格) を**そのまま残す**。
その制約の中で、既存研究が「効く」と示している手法を、コスト・証拠の強さ・本設計との相性で並べる。
9/19〜20 のサーベイ (ループ / 蒸留 / 自己対戦 / 功績配分 / 入力表現 / レート重み) と重複するものは省く。

**出発点の事実 (コードで確認)**: 現在の学習には dropout・stochastic depth・label smoothing・
重み平均 (EMA/SWA)・学習率スケジューラ・warmup・early stopping が**一つも入っていない**。
過学習が律速 (train 47.3 / val 41.5、差が拡大) なのに、正則化がゼロという状態である。
また `rotate_sfen` は tokenizer の docstring に書かれているだけで**定義が存在せず**、盤は絶対座標のまま
`turn` 埋め込みで先後を区別している。→ 180° 回転 + 先後入替の増強は未実装。

## A. 正則化と最適化 — アーキテクチャ不変・最安・過学習に直撃

| 手法 | 根拠 | 本設計との相性 | コスト |
|---|---|---|---|
| **重みの EMA / SWA** | Lc0 は Test30 で SWA を導入 (過学習の抑制と強さ・学習速度の改善、Veedrac のブログ) ※二次情報。KataGo はスナップショットの EMA (減衰 0.75) で網を選ぶ (arXiv:1902.10565)。EMA の一般論: 雑音ラベル耐性・較正・汎化の改善、**学習率の減衰を弱くできる** (arXiv:2411.18704)。EMAgnet は PPO を EMA へ引き戻す正則化 (arXiv:2606.23995、既調査) | 完全に互換。推論時に EMA 重みを使うだけ | **数行** |
| **学習率スケジュール + warmup** | 標準。現状は固定 2e-4 で 13 時間 | 互換 | 数行 |
| **dropout / stochastic depth** | 小データの Transformer は帰納バイアス不足で過学習しやすく、dropout 0.3〜0.5 や sub-layer をランダムに飛ばす stochastic depth が定石 (Huang et al. 2016 ほか) | 互換。会議ループの再適用層にも同じ確率で効かせる | 数行 |
| **label smoothing** | 標準。one-hot の指し手教師を軟化 | 互換。MultiPV 教師 (効かなかった) より弱い軟化 | 数行 |
| **early stopping を外部基準で** | val 一致率は外部強さと相関しない (r=+0.40、e3 以降逆相関) と実測済み | — | 運用の変更 |

→ **最初にやる。** 全部合わせて実装半日、効果は 1 epoch (13h) で読める。証拠が最も一般的で、対象 (過学習) が
診断済みなので、期待値が最も高い。

## B. データ増強 — 180° 回転 + 先後入替で実質 2 倍

将棋の盤は 180° 回転で対称 (NNUE も回転を使う、chessprogramming.org)。AlphaZero はチェス・将棋で増強を
しなかったが、それは「対称性を仮定できない」という保守的判断で、180° + 先後入替は将棋では厳密な対称である。

本設計での成立条件を確認した:
- trunk はトークンの並びを使わない (埋め込みは species/position/flag/turn のみ) → 並び替えに不変
- `MonotonicValueMixing.hyper` は**トークン添字ごと**に α_i を出す → ただし並びは piece_id 辞書順で固定なので、
  180° 鏡像は**固定された添字の置換** (例: B22 ↔ B88、K51 ↔ K59) で表せる
- 方策の index = 駒トークン × 81 + 移動先 も同じ置換 + マスの回転で写せる
- 感情 GRU・絆 EMA は駒ごとに独立なので置換と可換

→ 実装 1 日 (tokenizer に置換表、dataset に増強フラグ、action の写像、テスト)。データが 22.4M → 44.8M 相当。
年拡大 (1.68x) と掛け合わせれば **3.4x** に届く。

## C. 補助ターゲット — 駒トークンの上に自然に乗るもの

| 手法 | 根拠 | 本設計での形 |
|---|---|---|
| **future heads (次の 2 手を予測)** | Lc0 BT4 が「次の 2 ply の指し手」を予測する補助ヘッドを追加 (OpenChess / chessengines.blogspot の報告、公式ブログには記載なし ※二次情報) | 駒トークンごとに「次に相手が動かす駒はどれか」「その次に自分が動かす駒はどれか」を予測。**駒の分解と相性がよい** (手 = 駒 × 移動先) |
| **moves-left (残り手数)** | Lc0 の moves-left head、Czech らの ply 回帰 (+33 Elo の一部、既調査) | 混合器の pooled h̄ から 1 スカラー。`plies_left` は既に `SequenceDataset` が持っている (運命損失の実装時に追加済み) |
| **WDL + categorical value** | Lc0 の WDL head、BT4 の categorical value head (q の分布)、Czech ら | V(s) を 3 値 / n 値分類に。**V_i の単調混合はそのまま**で、混合後の出力側だけ変える |
| **駒ごとの短期事象** | 既に desire ラベル (k=4: survive/attack/promote/…) がある。運命損失はその長期版 | 統合できる: 運命 = desire の k→∞ 版と位置づけ、γ で滑らかに繋ぐ |
| **チェスとの同時学習** | Wan & Kaneko (ICONIP 2018): チェスと将棋の評価関数を共有層で同時学習し、限られた学習ステップで両方の精度が改善 | 駒トークンはチェスにも使える (32 駒) が、パイプラインが無い。**後回し** |

## D. 値ターゲット — 探索なしのブートストラップ

dlshogi の value 損失は CE(勝敗) + CE(探索評価値) の和で、探索評価値でブートストラップする (山岡氏のブログ)。
AlphaGo は V = (1−λ)·v_θ + λ·z の混合で λ=0.5 が最強 (Silver et al. 2016)。TreeStrap (Veness 2009) は探索木で
ブートストラップ。**本設計は探索を持たないが、時間方向のブートストラップは可能**:

    target_t = (1−λ)·z + λ·V_frozen(s_{t+k})     k 手先の凍結モデルの価値を教師に混ぜる

z は 1 局 1 ビットの粗い教師で、これが過学習の一因になりうる (全局面が同じ z を共有)。k 手先の V は局面ごとに
変わる密な教師で、外部エンジンが要らない。運命損失 (V_i の教師) と同じ動機を、V(s) 側で実現する形。
→ 実装半日。λ と k の掃引が要る。

## E. attention の幾何 — 32 パラメータの置き換え

| 手法 | 根拠 | 本設計での形 |
|---|---|---|
| **相対位置バイアス (T5 流)** | Shaw et al. 2018、T5 の学習可能な相対バイアス。Chessformer は「桂馬・角・飛車の動きで近い」マス対に特化した符号化 | 駒対 (i, j) の (Δ筋, Δ段) ∈ 17×17 を引く表 × 8 ヘッド = 2,312 パラメータ (現行 24 の 100 倍だが全体の 0.05%)。持ち駒は「盤外」の 1 バケット |
| **層ごとに別のバイアス** | Lc0 の trainable bias は **層ごと** (64×64×h / 層)。本設計は 6 層で同じ 32 個を共有 | `effect_bias` と `relation_bias` を層数ぶん複製。零初期化なので warm start 可 |
| **smolgen (局面依存の attention logit)** | Lc0 BT2〜: 局面を 256 次元に圧縮 → 256×4096 の共有射影 → ヘッドごとの補助 logit。「50% 大きいモデル相当を 10% の遅延で」(公式ブログ) | pooled h̄ (既に混合器で計算済み) → 40×40×8 の logit を生成する小さな射影。**駒 40 なので 64 マスより安い** |

幾何は学習で獲得できる (Chessformer の解析) が、それは 15 層・1024 次元の話。6 層・256 次元・22M 局面では
節約の価値が大きい可能性がある。ただし効果は 0.03 前後と見込み、**測定が直るまで判定できない**。

## F. 埋め込みの強化

Lc0 BT3 は埋め込み直後に FFN を 1 段入れ、「15% 大きいモデル相当を 5% の遅延で」(公式ブログ)。本設計の
埋め込みは 4 表の和 + LayerNorm だけ。species/position/flag/turn を**連結**して小 FFN に通す形にすれば、
「角が 2二にいる」という組合せを最初の層より前に作れる。Czech らの導出特徴 (駒得差・王手・持ち駒枚数、
既調査) をここに足すのが自然。→ 半日、warm start は埋め込み部だけ再初期化。

## 何が新規性と衝突しないか (確認)

- 駒トークン 40 → すべて維持。B の置換も駒単位
- 会議ループ → A の dropout は再適用層にも同じ確率で。C の future heads は会議後の hidden から出す
- V_i の単調混合 → C/D は混合**後**の V の教師と出力形式を変えるだけ。V_i と α_i はそのまま
- 内面 (感情/絆/性格) → 一切触らない
- 運命損失・転生保存則 → C の駒ごと事象・D のブートストラップと**同じ動機の別実装**。併用可
