### 新規性の主張をどこに置くか

**「永続する駒トークンだからこそ書ける 2 つの教師信号」**に置く。

- **運命** — 時間方向: この駒は何手後に取られる / 成る / 生き残るか (局面あたり 40 個、全局面に付く)
- **転生保存則** — 所属方向: 取られて相手の持ち駒になる瞬間、価値は消えず移転する

マストークン系 (Lc0 / Chessformer / Ruoss) はどちらも**表現できない**。マスは駒の運命を持たず、
捕獲でマスの中身が消えるので移転も定義できない。この 2 つを合わせて「駒の一生を教師にする」
と呼ぶ。機構としての新規性は A (保存則) にあり、運命はそれを時間方向に延長したもの。

## 統合案

### 核: 駒の一生を教師にする (新規性)

```
運命損失     f_i(t) = -γ^k (k 手後に取られる) / +γ^k·b (成る・詰ます) / +γ^(T-t)·c (生き残る)
             L_fate = λ_f Σ_i mask_i (V_i(t) - f_i(t))²

転生保存則   駒 i が t 手目に取られたとき
             所有者相対:  V_i(t+1) ≈ κ_species · V_i(t-1)     κ は学習する移転係数
             絶対座標:    V_i^abs(t+1) ≈ -V_i^abs(t-1)
             L_rebirth = λ_r Σ_{捕獲事象} (V_i(t+1) - κ_s V_i(t-1))²

混合器       V(s) = tanh(Σ_i α_i V_i + b)、α_i ≥ 0 は状態依存
             L_value = WDL 交差エントロピー + β (残り手数)²   ← Czech et al. の形
```

- `piece_value_i` は既に出力にあるが、**どの損失にも使われていない** (`heads.py: MonotonicValueMixing`)
- 捕獲事象はシャードの `position → HAND_POSITION` 遷移と `game_index` から取れる。1 局 20〜40 回
- 捨て駒は α_i が下がることで吸収する設計。λ_f, λ_r が大きいと V_i が教師に引かれて V の精度を
  落とす可能性 → 掃引が要る
- 持ち駒の価値は将棋で最も難しい量で、保存則はそれを盤上の価値と学習した換算則で結ぶ
- **マスの運命** f_sq(t) = 「k 手後にどちらが支配しているか」: マストークン側の密な教師。
  マストークンが要るので段 3 で器が入ってから (段 5 ではなく段 3 と同時に試す)

### 器: 駒×マスの二部 Transformer (強さの賭け、新規性は主張しない)

現行 trunk の盲点は 3 つ: 空きマスにトークンがない (玉の逃げ道・打ち場所が実体を持たない)、
打ちが hand→square の関係として表せない、幾何が 3 値 × 8 ヘッド = 24 パラメータしかない。

```
駒トークン 40   個性・気分・欲求・キャリア・運命 (今と同じ場所に住む)
マストークン 81  空き・支配・幾何・打ち先・マスの運命 (新設)

1 層 = 駒→駒 self-attn         (現行)
     + 駒→マス cross-attn      駒種の動き方でマスク: 「私はどこへ行ける」
     + マス→駒 cross-attn      「誰が私を支配している」
     + マス→マス self-attn     段・筋・斜めの相対バイアス
```

- 利きは本来「駒→マス」の関係。24 パラメータの現行バイアスをルールに沿った接続に置き換える
- 遮りは「間の駒トークンの有無」をマス側が知ることで表せる
- 打ちは持ち駒トークン → 空きマストークンの cross-attn そのもの
- 方策ヘッドは現行の「駒 × 81 マス × 成」のままで整合する

段階的に入れる: 24 パラメータの利きバイアス → 線・遮り・距離の相対バイアス (段 2、warm start 可)
→ マストークン + 駒↔マス cross-attn (段 3、新設部は warm start 不可)。
**幾何は学習で獲得できる**ことが示されているので、効くとすれば 5M・156k 局という小規模だから。

### 会議: 入札均衡 (既知機構 N-FPN の適用、ループに意味を与える)

```
駒 i の効用   u_i(m) = 手 m による自分の運命の変化 (MoveConditionedMLP で予測)
入札の更新   b_i^{r+1} = f(h_i, Σ_j α_j b_j^r)     他駒の入札への最適応答
不動点       b* = 会議の結論。手 = argmax_{(i,m)} b*_i(m)
学習         N-FPN 流の Jacobian-free 逆伝播、または打ち切り展開 (現行 R)
```

- R を増やしても強くならない原因 (どのラウンドも同じ入力・同じ目標) を、
  「ラウンド = 最適応答の 1 反復」と定義し直すことで解く
- **各反復の注意の規則 (照準)**: ラウンド r の共有層は、前ラウンドで最高 bid だった駒を照準に
  走らせる — その駒の到達マス (駒→マス マスクの範囲) と関係駒に attention 予算を寄せる。
  最適応答 b_i^{r+1} = f(h_i, ·) の h_i をこの照準つき attention で計算する。
  「深く考える = 別の駒の立場で考え直す」になり、ラウンドごとに見えるものが変わる。
  これは 9/20 初版の「視点会議」で、入札均衡の中に注意の規則として収める
- **運命が私的効用を与える**ので均衡が自明にならない (歩は生き残りたい、チームは捨てたい)
- 入札が収束したら止まる = 停止ヘッドなしの適応的 R。random loop sampling は打ち切り深さへの頑健化
- 新規性は主張しない。「N-FPN を駒オークションに適用した」と書く

### 三つの関係

運命 → 転生保存則 (時間方向と所属方向、同じ V_i の教師) → 入札均衡 (運命が効用、照準は
最高 bid の駒) → 器 (運命を当てるには幾何が要る、照準の範囲は駒→マス マスク)。
核は最初の 2 つで、残りはそれを強さに繋げる手段。9/20 初版の ①器 ②教師 ③会議 は
それぞれ 器 / 核 / 会議の注意の規則 として全部ここに入っている。

## 実装メモ (2026-09-20 夜、段 1 の実装で確定したこと)

- 運命の事象 (`fate_capture` / `fate_promote` / `fate_mate` / `plies_left`) は `data/sequence.compute_fate` が
  行データから引く。ラベル生成スクリプトも側面ファイルも無い。f_i の γ, b, c, m は `LossConfig`
- 転生保存則は `mood_distill.run_epoch` が前手の V_i (detach) を持ち越して `distill.rebirth_loss` を呼ぶ
- **κ_species はモデルの外** (学習ループの `nn.Parameter`、weight decay なし、チェックポイントの
  `rebirth_kappa` キー)。モデルの state_dict に足すと旧チェックポイントの strict 読み込みが全部壊れるため
- V_i は tanh を通らない生の線形出力なので、運命損失は V_i を [-1, 1] の尺度に引き寄せる。混合器の
  α と bias がそれを吸収する設計だが、λ_f = 1.0 は初期に損失を支配する (煙試験で fate 2.2 vs value 0.5)。
  段 1 はこのまま走らせ、効かなければ λ の掃引を先にやる
- 段 1 の 3 本は `checkpoints/ops/stage1.sh`。対 Háo (`eval_vs_engine.py`) と凍結アンカー
  (`eval_vs_model.py`、対 phase37_e3) の両方を測り、対照との対応あり検定を自動出力する
- テスト `tests/test_fate.py` (運命の計数・優先順位・持ち駒のマスク・κ の勾配)。324 passed

## 段階と門

各段は前段の勝者から warm start、対照と同条件で 1 epoch、外部基準 100 局、対応あり検定。
門を通らなければ進まない。

| 段 | 内容 | 走行 | コスト | 確かめること |
|---|---|---|---|---|
| 0 | e4 (走行中) | — | 12h | trunk の学習量で伸びるか |
| **1** | **対照 / 運命 / 運命+転生保存則** の 3 本 | 0 の勝者から | 1 日 + 12h×3 | 駒の一生が教師として効くか。新規性の核の検証 |
| 2 | 幾何バイアス置換 | 1 の勝者 | 半日 + 12h | 幾何が穴か |
| 3 | マストークン + cross-attn + **マスの運命** | 駒層のみ | 1 日 + 36h | 空きマスと打ち、マス側の教師 |
| 4 | 入札均衡会議 (照準つき) | 3 (or 2) の勝者 | 1 週間 | R が強さを買うか |
| 5 | 全統合 | 4 の勝者 | — | — |

段 1 の実装 (ラベル生成 + 損失 2 項) は CPU で書けるので e4 の裏で始められる。

## 危険 (正直に)

- 新規性の主張は A に依存する。Web 検索 14 回で無かったが、**Semantic Scholar と GPW / GI 研の
  日本語文献を発表後に本格的に当てる**まで確定としない
- 運命 ≠ 価値、保存則 ≠ 厳密 (持ち駒の歩と盤上の歩は違う)。どちらも λ で緩める設計だが、
  効かなければ「解釈のための教師であって強さのためではない」が結論になる。それも知見
- 段 3 以降は最も効く場所 (trunk 94.68%) を最も大きく変える賭け
- すべて段 0 (trunk の学習量) の上に乗る
