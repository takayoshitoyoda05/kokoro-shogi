# Kokoro-Shogi（こころ将棋）

**駒が心を持つ将棋 AI。** 盤面ではなく 40 枚の駒それぞれを 1 人の登場人物として扱い、
駒の欲求・性格・感情から一手を決め、その内面を Unity の 3D 盤面で観戦できます。

> 歩が怯えて青ざめ、金と玉が絆の光で結ばれ、駒たちの会議が吹き出しで交わされ、実況が流れる。

## 1. このプロジェクトは何か

### 発想

ふつうの将棋 AI は「盤面」をひとつの評価関数で見て、最善手を探索します。
このプロジェクトは発想を変えて、**盤上と駒台にある 40 枚の駒を、それぞれ 1 人の登場人物**として
扱います。

- 各駒が **欲求**（生き残りたい・攻めたい・成りたい・守りたい・前に出たい・打たれたい）を持つ
- 駒の種類ごとの **性格** が、どの欲求を重く見るかを決める
- 対局中の出来事で **感情** が動く（近くで味方が取られると強く動揺する）
- 長く守り合った駒どうしには **絆** が育つ
- 一手は駒たちの **会議**（主張の競り合い）で決まり、議事録が残る
- 取られた駒は消えず、**相手の駒として転生**して盤に戻る

こうして決まった一手を、Unity では駒の色・光・吹き出し・実況として表現します。

### 探索をしない

この AI は **先読み（木探索）を一切しません**。局面を 1 回計算して 1 手を返します。
探索で手が決まると、駒の欲求や性格が飾りになってしまうからです。
そのぶん強さでは探索型の将棋 AI に及びません。強さの実測と、試して効かなかった施策は
[技術報告](./docs/TECHNICAL_REPORT.md) に検定値つきで記録してあります。

### 誰が作っているか

学生チーム 5 人（AI 1 名 / Unity 2 名 / Blender 2 名）の作品です。
Python 側（AI）と Unity 側は [`docs/INTERFACE.md`](./docs/INTERFACE.md) の JSON 契約だけで
つながっていて、互いの内部を知らなくても開発できるようにしてあります。

## 2. AI はどうやって指しているのか

局面を入れてから手が出るまでを、順に説明します。数字は
[技術報告](./docs/TECHNICAL_REPORT.md) と同じものです。

```
局面
 │  ① 駒 40 枚を数字にする
 ▼
駒トークン 40 個（各 256 個の数字）
 │  ② Transformer 6 層で、駒どうしの関係を読む
 ▼
駒ごとの表現 40 個
 │  ③ 各駒が「この手を指したい」と主張する（欲求 × 性格 + 自由項）
 │  ④ 会議で主張を往復させる（同じ層をもう一度通す）
 ▼
40 駒 × 81 マス × 成り = 6,480 通りの主張
 │  ⑤ 全部まとめて 1 つの softmax → 一番強い主張が通る
 ▼
指し手                                   ⑥ 別枝: 駒ごとの価値を混ぜて形勢を出す
```

### ① 駒をトークンにする

盤の 81 マスではなく、**駒 40 枚**をそれぞれトークンにします。各駒は 4 つの整数で表されます。

| 数字 | 意味 |
|---|---|
| 駒種（0〜13） | 歩・香・桂・銀・金・角・飛・玉と、その成駒 |
| 位置（0〜82） | 盤の 81 マス、**81 = 先手の駒台、82 = 後手の駒台** |
| 持ち主（0 / 1） | 先手 / 後手 |
| 成り（0 / 1） | 成っているか |

各駒には `P77_gen0_0029`（7七にいた歩）のような ID が付き、**対局中ずっと変わりません**。
取られても ID は消えず、位置が「駒台」になり持ち主が反転するだけです。
打ち直されれば盤に戻ります。これが「転生」で、感情や絆もそのまま引き継がれます。
トークン数が常に 40 で固定されるので、計算の形が対局中に変わりません。

### ② Transformer で駒どうしの関係を読む

40 個のトークンを **6 層の Transformer**（幅 256、8 ヘッド、FFN 1024）に通します。
ChatGPT などの言語 AI と同じ仕組みで、言語の「単語」の代わりに「駒」を扱います。

各層で、それぞれの駒が「他のどの駒をどれだけ見るか」を計算し（attention）、
見た相手の情報を自分に取り込みます。8 ヘッドは 8 通りの見方を並列に持つ仕組みで、
学習済みモデルを開くと「取り合いを見るヘッド」「守りの構造を見るヘッド」
「長く続いた絆だけを見るヘッド」に自発的に分かれています。

将棋のルールから来る情報は、attention への **足し算のバイアス**として入れています。
「駒 i が敵駒 j を取れる」「駒 i が味方 j を守っている」の関係（3 種類 × 8 ヘッド = 24 個）と、
絆の強さ（8 個）で、**合計 32 個のパラメータ**です。将棋の幾何のほとんどは、
この 32 個ではなく残りの 470 万個が学習で獲得しています。

### ③ 各駒が主張する — 欲求 × 性格 + 自由項

Transformer から出た駒 i の表現から、「手 a を指したい度合い」を作ります。

```
s_i(a) = ⟨ 性格 w_i , 欲求 d_i(a) ⟩ + 自由項 g_i(a)
```

- **欲求 d_i(a)**（6 軸、各 0〜1）: この手を指すと「生き残れそうか」「攻めになるか」「成れるか」
  「守りになるか」「前に出られるか」「打たれることになるか」
- **性格 w_i**（6 個、必ず正）: 駒種ごとの性格・個体の性格・今の感情から作る。
  正の値に限ることで「この駒は生存を重く見ている」と読めるようにしてあります
- **自由項 g_i(a)**: 欲求では説明できない残り。学習中に小さく保つ罰則をかけるので、
  それでも大きい手は「本能に反した大局的判断」= 捨て駒の検出器になります

### ④ 会議 — 同じ層をもう一度通す

各駒の主張の上位 8 手を「提案」として取り出し、駒 40 個の後ろに並べて、
**Transformer の 5 層目と 6 層目をもう一度通します**。提案を見た駒たちが主張を作り直す、
というのが会議 1 ラウンドです。既定で 2 ラウンド回します。

新しい層は作らず既存の層を使い回すので、ラウンド数は学習後でも変えられます。
議事録（各ラウンドの上位提案と強さ）は Unity に送られ、吹き出しと実況になります。

### ⑤ 全駒まとめて 1 つの softmax — これが「調停」

40 駒 × 81 マス × 成る/成らない = **6,480 通りの主張を、まとめて 1 つの softmax** にかけます。

駒ごとに正規化しないのが要点です。分母を全駒で共有するので、「ある駒の主張が強くなれば
別の駒の確率が下がる」という競合が、そのまま 1 つの微分可能な式になります。
これが「駒たちが競り合って一手を決める」の実体です。ルール上指せない手は候補から外します。

### ⑥ 形勢 — 駒ごとの価値を混ぜる

指し手とは別に、「今の形勢はどちらが有利か」（−1〜+1）も出します。

```
V = tanh( Σ_i α_i × V_i + b )       α_i ≥ 0、Σ α_i = 1
```

各駒が価値 V_i を 1 つずつ出し、**発言力 α_i** で重み付けして混ぜます。
α_i が 0 以上なので「駒 i の判断が上がれば全体も下がらない」が保証されます。
この α_i は Unity に送られ、**その駒がいま形勢にどれだけ効いているか**として駒の光り方になります。

### 手をまたいで持ち回る 3 つの状態

| 状態 | 中身 | 更新のしかた |
|---|---|---|
| **感情**（駒ごとに 32 次元） | Unity に送る fear / aggression / valence の元 | 1 手ごとに 9 種類の出来事で更新。「味方が取られた」は**事件現場からの距離で減衰**（2 マスで約 1/e）して全駒に伝わる |
| **絆**（駒のペアごと） | 長く守り合った関係 | 守り合う状態を時間で積み重ねる（10 手続くと約 0.65） |
| **個体性格**（駒ごとに 16 次元） | 対局をまたいで蓄積 | データベースに保存 |

9 種類の出来事: 自分が動いた / 取った / 取られた / 成った / 味方が取られた / 敵が取られた /
自分が狙われている / 自玉が王手されている / 駒得の増減。

### パラメータはどこにあるか

| 部品 | パラメータ | 割合 |
|---|---:|---:|
| Transformer 6 層 | 4,774,176 | **95.47%** |
| 会議の提案埋め込み | 108,032 | 2.16% |
| 形勢の混合 | 76,586 | 1.53% |
| 欲求のヘッド | 20,838 | 0.42% |
| 自由項のヘッド | 20,673 | 0.41% |
| 性格 | 518 | 0.01% |
| **合計** | **5,000,823** | 100% |

このほかにモデルの外で持つ感情 GRU が 4,128 個あります。「こころ」に関わる部分
（性格 518 + 感情 4,128 + 絆 8）は全体の **0.09%** で、強さはほぼ Transformer が担っています。

## 3. どうやって学習させたのか

### 棋譜から学ぶ（主軸）

[floodgate](http://wdoor.c.u-tokyo.ac.jp/shogi/)（コンピュータ将棋の対局サーバ）の公開棋譜
**155,992 局・約 2,240 万局面**から学習しました。

- **指し手**: 棋譜で実際に指された手を正解とする
- **形勢**: 局の勝敗（勝ち +1 / 引き分け 0 / 負け −1）を正解とする
- **欲求 6 軸**: 「この駒は 4 手後に生き残っていたか」「4 手以内に成ったか」などを
  **棋譜からルールで自動生成**する。人手のラベル付けはゼロ

感情は 1 局を通して引き継がれるので、局面をバラバラにせず **1 局を頭から順に**学習します
（16 手ごとに区切って逆伝播）。1 周（1 エポック）に GPU で約 13 時間かかります。

### 自己対戦と文化リーグ（補助）

棋譜で学んだモデル同士を戦わせて勝った側の手を強化する **自己対戦強化学習（PPO）** と、
性格の異なる集団を競わせて淘汰する **文化リーグ** を、その上に重ねています。
同梱している 2 つのモデルは文化リーグの産物で、6 つの「文化」（駒種の性格の組）を選べます。

## 5. 動かしてみる

Python 3.12 と [uv](https://docs.astral.sh/uv/) が必要です。

```bash
git clone https://github.com/takayoshitoyoda05/kokoro-shogi.git
cd kokoro-shogi
uv sync --group train        # PyTorch を含む依存一式
```

学習済みモデルが 2 つ同梱されているので、**clone すればすぐ対局できます**。

### まず動くか確かめる（Unity 不要・数十秒）

```bash
uv run python scripts/play_server.py --selfcheck
```

乱択相手に 1 局を終局まで指します。起動直後の 1 行目に、どのモデルと機能が載ったかが出ます。

```
checkpoint: league.pt / culture: culture1 / device: cpu / tau: 0.0 / mood: 感情GRU / relations: r_ij状態 / council: ON
  ply   2 eval +0.053  2ラウンドの議論で形勢が動いた。当初は△玉の主張が通りかけたが、最後は△歩が8c8dを押し切った。
  ...
selfcheck: 42 手で終局 (人間の手 21 回, 0.9s, 0.02s/手) / career 40 駒 / MVP B22_gen0_0006
```

末尾 3 つが `感情GRU` / `r_ij状態` / `ON` になっていれば内面つきで動いています。
`ply` の行に出ているのが、**その手を決めた会議の実況**です。

### Unity の 3D 盤面で観戦・対局する

Python を先に起動してから Unity を Play してください（逆順では繋がりません）。

```bash
uv run python scripts/play_server.py --host 0.0.0.0
```

Unity プロジェクトは `unity/KokoroShogi/` を Unity Hub で開きます。

### 同梱モデルと「文化」

| ファイル | 中身 |
|---|---|
| `checkpoints/league_E2b_grace/league.pt`（既定） | 文化リーグ（猶予つき淘汰） |
| `checkpoints/league_E7_ema/league.pt` | 文化リーグ（適応度 EMA） |

`league.pt` は**ひとつの共有ネットワークと 6 つの「文化」**（駒種の性格パラメータ）を持っていて、
どの文化で指すかを選べます。同じ盤面でも、生存を重んじる文化と攻撃を重んじる文化では違う手を指します。

```bash
uv run python scripts/play_server.py --culture culture2
uv run python scripts/play_server.py --checkpoint checkpoints/league_E7_ema/league.pt
```

> **測り方について**: 自分の過去のモデルと対戦させると強くなったように見えても、
> 外部のエンジンを相手にすると順位が入れ替わることがありました。
> **自己対戦の勝率は、自分の系列の中でしか意味を持ちません。**
> 強さの実測値と、効いた施策・効かなかった施策は
> [技術報告](./docs/TECHNICAL_REPORT.md) にまとめてあります。

その他の主な引数: `--human white`（人間が後手）/ `--tau 0.1`（手を揺らす。0 なら常に最善手）/
`--device cuda` / `--port` / `--max-plies`。

### 自分で学習させる

```bash
uv run python scripts/download_floodgate.py --year 2024           # 年次アーカイブ（約 350MB）
uv run python scripts/make_labels.py --csa-dir data/floodgate/csa  # 棋譜 → 学習用シャード
uv run python -m kokoro_shogi.train.mood_distill \
    --shard-dir data/shards --relations --council --amp --epochs 1
```

## 6. リポジトリの構成

```
  train/              棋譜からの蒸留、自己対戦 PPO、文化リーグ
  data/               floodgate 棋譜の読み込み、欲求ラベルの自動生成、シャード

docs/                 技術報告、データ契約、設計書、判断記録
tests/                18 ファイル、330 テスト
```

### 技術的に主張していること

1. **方策の駒粒度への分解** — 指し手の確率を「どの駒が、どこへ」に分解し、駒ごとの欲求と性格で
   説明できる形にしています。駒をトークンにする将棋 AI の先行例は見つかりませんでした
   （Leela・Chessformer・Ruoss らはいずれもマスか文字列）。
   なお**各駒が独立した方策を持つわけではなく**、ひとつのネットワークが全駒ぶんをまとめて計算します
2. **持ち駒 = 駒の転生** — 捕獲で駒の所有権が敵に移る現象は、将棋にしか存在しません。
   駒トークンが消えずに持ち主だけ反転するので、感情や絆を引き継いだまま敵として盤に戻ります
3. **解釈可能性と強さのトレードオフの定量化** — 「欲求でどれだけ説明できるか」と一致率の曲線を、
   正則化係数を振って描けます

否定的な結果も同じ重みで公開しています。内面を強化学習で育てる路線は、外部のエンジンを基準に
測ると有害でした。自己対戦の勝率は系統の外では通用しませんでした。
[技術報告](./docs/TECHNICAL_REPORT.md) に検定値つきで記録してあります。
