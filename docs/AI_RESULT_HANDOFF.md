# Python担当者への依頼：終局時の勝敗をUnityへ通知してください

作成日：2026-09-19

## お願いしたいこと

**Pythonで対局が終わったときに、「誰が勝ったか」「なぜ終わったか」をUnityへ送ってください。**

現在、UnityでAIと対局して詰みの局面になると、操作は進まなくなりますが、
`MainGameCanvas` の `TextResultInfo` に結果が表示されません。
コードを確認したところ、Pythonには終局判定がある一方、送信メッセージに勝敗がありませんでした。

学習モデルの変更や再学習は必要ありません。対応箇所は通信データの定義と対局セッションです。

## 今の処理と、足りない情報

| 処理 | 現在の実装 |
|---|---|
| 終局判定 | `src/kokoro_shogi/server/game_session.py` の `_finished()` が判定する |
| 最後の盤面 | `state_update` をUnityに送る |
| 終局時の送信 | `_finish()` が `career`（駒ごとの成績）を送る |
| 勝者・終了理由 | `career` にも他のメッセージにも含まれていない |
| 次の合法手一覧 | 終局時は `legal_moves` を送らない |
| Unityの旧処理 | 空の合法手一覧を受け取った場合に結果判定へ進むため、サーバーの終局とつながらない |

つまり、Pythonは「対局終了」と判断していますが、Unityにはその結果が明確に伝わっていません。
通信が遅れている状態と、対局が終わった状態をUnity側で区別できる情報が必要です。

なお、今回の原因はコードから確認したものです。ユーザーが試した対局そのもののSFENや
通信ログは取得していません。「どの駒も次に取られる」だけでは詰みとは限らず、
玉への王手を合法手で回避できないかどうかをPython側で判断します。

## 依頼する送信形式

既存の `career` に、終局時だけ `result` を追加する案です。
Unity側には、この形式の受信・表示処理を準備済みです。

```json
{
  "schema": "1.0",
  "type": "career",
  "pieces": [],
  "last_game_mvp": null,
  "result": {
    "winner": "white",
    "human": 0,
    "reason": "checkmate"
  }
}
```

この例は「人間が先手、後手のAIが詰ませて勝った」を表します。
`pieces` と `last_game_mvp` は説明用に省略した値です。実装では現在の成績集計をそのまま残してください。

| フィールド | 値と意味 |
|---|---|
| `winner` | `black`＝先手勝ち、`white`＝後手勝ち、`draw`＝引き分け扱い |
| `human` | `0`＝人間が先手、`1`＝人間が後手 |
| `reason` | 下表の終了理由 |

| `reason` | 意味 | 勝者 |
|---|---|---|
| `checkmate` | 王手されていて合法手がない | 現在の手番と反対側 |
| `no_legal_moves` | 王手ではないが合法手がない | 現在の手番と反対側 |
| `repetition` | 現在の実装で引き分けと判定する千日手 | `draw` |
| `max_plies` | 手数上限に到達 | `draw` |
| `resign` | 人間が投了 | AI側 |
| `engine_no_move` | 合法手があるのにエンジンが手を返せない | 暫定的に `draw`。画面には異常終了の理由を表示 |

`engine_no_move` は詰みと誤表示しないための例外扱いです。
連続王手の千日手など、現在の `_finished()` が扱っていない終局規則の追加はこの依頼に含めません。

## 通知の順序とUnity側の動作

通常の終局は、次の順番で送ってください。

```text
最後の state_update
→ result 付き career
→ 対局セッションを待機状態にする（以後の着手を受け付けない）
```

これはクライアントから見た通知の順序です。内部の状態を待機に戻してから
メッセージ列を返す現在の実装を変える必要はありません。
投了時は盤面が変わらないので、追加の `state_update` は不要です。

Unity側は次の処理を準備済みです。

1. `ServerBoardSynchronizer.ReceiveCareer()` が `career.result` を受け取る。
2. 盤面操作を止め、受信済みの最後の着手とカメラ演出が終わるまで待つ。
3. `GameSceneDirector.ShowServerResult()` が `TextResultInfo` を有効にする。
4. 「人間の勝ち」「AIの勝ち」「引き分け」と再戦・タイトルボタンを表示する。

`career` は起動時の成績や旧ログにも使われるため、**`result` のない `career` を終局扱いにしない**設計です。
空の `legal_moves` を送るだけでは引き分け・投了の理由や人間の手番が伝わらないため、
準備済みのUnity実装に合わせて `career.result` を送ってください。

## 完了の確認

- 人間が詰ませたときは「人間の勝ち」、AIが詰ませたときは「AIの勝ち」が出る。
- 人間が後手の設定でも勝者の表示が逆転しない。
- 手数上限では「引き分け」、投了では「AIの勝ち」が出る。
- 王手でも逃げ道がある場合は結果画面にならない。
- 最後の盤面が表示され、演出後に結果が出る。結果が直後に消えない。
- 終了後の着手を受け付けず、新しい対局を開始できる。
