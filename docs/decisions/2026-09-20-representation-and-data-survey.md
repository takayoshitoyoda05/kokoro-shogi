# 2026-09-20 サーベイ: trunk の入力表現・値損失・データの使い方

9/19 の 2 本のサーベイは「ループ / 蒸留 / 自己対戦 / 功績配分 / アーキテクチャ」を扱った。
今回は 9/20 に分かったこと — **強さの 94.68% は trunk にあり、9/19 に試した施策はすべて
trunk の外側だった** — を受けて、trunk そのものの入力・損失・学習データに絞って調べた。

結論から言うと、**今まで一度も触っていない安い改善候補が 3 つ**見つかった。

## 1. 入力表現と値損失 ★最有力

Czech et al., *Representation Matters for Mastering Chess: Improved Feature Representation in
AlphaZero Outperforms Switching to Transformers* (arXiv:2304.14918, ECAI 2024)

AlphaZero のチェスで、**アーキテクチャを触らずに入力表現と値損失だけを変えて +180 Elo**。
同じ論文で Vision Transformer への置き換えは +30 Elo しか出ず、**表現の改善が
アーキテクチャの変更を 150 Elo 上回った**。内訳:

| 変更 | 効果 |
|---|---|
| 入力表現 (39 → 52 プレーン) | **+97 Elo** |
| 値損失 (MSE → WDL + 残り手数) | **+33 Elo** |
| 両方 | **+180 Elo** |

入力に足したのは「既存の特徴から**導出できる**が、ネットに計算させると層を食うもの」:
両者の駒のグループマスク、市松模様、駒得差 (駒種ごと 5 プレーン)、異色バンド、
王手をかけている駒、持ち駒の枚数 (5 プレーン)。逆に手番の色プレーンと手数は**外した**。
著者いわく「導出可能でも前もって与えることでネットの容量が空く」。

値損失は MSE をやめ、**勝ち/引き分け/負けの 3 値分類 (WDL) の交差エントロピー + 残り手数の
回帰**にした:

```
ℓ = -α (WDL_t · log WDL_p) - π · log p + β (ply_t - ply_p)² + c‖θ‖²
```

### 本プロジェクトとの対応

**該当する。** 現状の入力は駒トークンあたり 4 つの埋め込みだけ
(`PieceTokenEmbedding`: species / position / flag / turn)。持ち駒は
`HAND_POSITION = (81, 82)` として position に入っているので情報自体はあるが、
**枚数の集計・駒得差・王手の有無・手数はどこにも入っていない**。

値損失は `nn.functional.mse_loss(output.value, value_target(...))` の素の MSE
(`src/kokoro_shogi/train/distill.py:129`)。**WDL 化も残り手数の補助損失も入っていない。**

注意: 論文の Elo は MCTS 付き AlphaZero での値なので、**探索なしの本プロジェクトで
同じ幅が出る保証はない**。ただし「表現 > アーキテクチャ」の順序自体は、
9/20 の観測 (内面 0.09% をいじっても動かない / trunk の epoch を足すと +0.11 動く) と整合する。

## 2. 棋力による重み付け学習 ★実装が一番安い

Li & Jiang, *Tracking vs. Deciding: The Dual-Capability Bottleneck in Searchless Chess
Transformers* (arXiv:2603.29761, 2026-03-31)

低レート棋譜を**足切りすると性能が落ちる**。代わりに**勾配の重みを下げて残す**。

| 方式 | 式 | 強さの比 | 高レート側の勾配寄与 |
|---|---|---|---|
| 一様 (現状) | w(e) = 1 | 1:1 | 5% |
| **線形** | w(e) = clip(α(e − e_min), w_min, 1) | **20:1** | 45% |
| 指数 | w(e) = exp(β(e − e_ref)) | 200:1 | 85% |

28M パラメータ・スケール変更なしで**線形重み付けのみ**の効果:
top-1 一致率 46.5% → 47.0%、直接対決 **40 勝 23 敗 37 分 (p = 0.043)**。
指数重み付けは検証損失は下がるのに性能が壊れた。**線形が最適点。**

### 本プロジェクトとの対応

**該当する。しかも一番安い。** `src/kokoro_shogi/data/floodgate.py` は CSA から
レーティングを**すでにパースしていて** (`GameRecord.ratings`)、それを
`min(record.ratings) < DEFAULT_MIN_RATING` (= **3000**) の**足切りにだけ使って捨てている**。

3,000 局の標本調査:

| | 割合 |
|---|---|
| 採用 | 43.1% |
| **レート不足で棄却** | **53.3%** |
| 手数・中断など | 2.9% |
| 解析不可 | 0.7% |

**半分以上をレートだけで捨てている。** 生 CSA は 360,865 局あるのに学習は 155,992 局。
足切りを緩めて線形重みに替えれば、**データ量がおよそ 2 倍になる**。
両者の低い方のレートは中央値 2592、90%点 4112、**23.7% はレート 0 (不明)**。

重要な但し書き: 論文が「足切りで落ちる」と言う理由は、
**指し手列から盤面を復元する能力 (state tracking) が低レート棋譜の多様性で育つ**から。
本プロジェクトは盤面を直接トークンで渡すので**この機構は当てはまらない**。
「重み付けのほうが足切りより良い」がそのまま移るとは限らず、**仮説として検証が要る**。
幸い対照実験は安い (同条件で足切り版と重み版を 1 epoch ずつ)。

## 3. 探索模倣からの脱却 (RL を再開するなら)

Miłosz, Duch & Grabowski, *Beyond Search-Imitation: Prior-Directed Exploration for
Searchless Chess* (arXiv:2608.27757, 2026-08-27) ※ 要旨のみ確認、本文は未読

MCTS の訪問回数を蒸留した探索なしネットを、**自己対戦 RL で 1 パスの強さに合わせ込む**。
エントロピーボーナスの代わりに**自分自身の MCTS 事前分布への順方向 KL**
(prior-directed exploration) を使い、温度をエントロピー適応にする。
約 2,000 ステップで詰将棋正答率 93.9% → 94.9%、4 手詰 77% → 81%。

### 本プロジェクトとの対応

**いまは該当しない。** 前提が「強い教師の探索を蒸留した土台がある」ことだが、
9/20 の実験でエンジン教師蒸留はこの規模では効果なし (p = 0.84) と分かっている。
また PPO 自体 9,200 iter で +0.01 しか動かず、路線としては閉じた。
土台が強くなってから再訪する。

## 着手の順序

| | 施策 | 想定コスト | 根拠の強さ |
|---|---|---|---|
| 1 | **値損失を WDL + 残り手数に** | 半日 (実装) + 12h (1 epoch) | 論文 +33 Elo。現状が素の MSE なのは確か |
| 2 | **レート線形重み付け + 足切り緩和** | 半日 (シャード再生成) + 12h | 論文 p=0.043。データが 2 倍になるのは確実 |
| 3 | **入力に導出特徴を足す** | 1〜2 日 | 論文 +97 Elo。ただし将棋向けの選定が要る |

いずれも **e4 (trunk の 4 epoch 目) の結果が出てから**着手する。
e4 が伸びていれば「trunk の学習をもっと回す」が先で、これらはその上に乗せる。
e4 が頭打ちなら、これらが次の本命になる。

1 と 2 は互いに独立なので、対照を取りながら片方ずつ入れられる。3 は将棋固有の
特徴選定 (王手、駒得差、持ち駒枚数、敵陣進入、利きの数) が要るので後回し。
