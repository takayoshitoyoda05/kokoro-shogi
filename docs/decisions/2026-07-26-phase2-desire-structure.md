- 日付: 2026-07-26
- 決めた人: Taka (A)
- 関連: `DESIGN.md` §3(3)-(6)(8) §4 §4a / Phase 2 Gate /
  [`2026-07-26-phase1-policy-and-baseline.md`](./2026-07-26-phase1-policy-and-baseline.md)

## 何を決めたか

DESIGN.md §3 の数式をコードに落とすとき、式だけでは決まらない点を確定させた。

### 1. Phase 1 と Phase 2 は「置き換え」ではなく `head=` で並存させる

`KokoroPolicy(head="plain" | "desire")`。

- `plain`: 素の src-dst スコア。**Gate1 (CNN比 -2%以内) はこちらで測る**
- `desire`: $s_{i,a} = \langle w_i, d_i(a)\rangle + g_i(a)$。$\lambda_g$ 掃引・
  解釈可能性の評価・Unityへ送る内面データはこちら

Gate1 が未通過のうちに Phase 1 の経路を消すと、後戻り (DESIGN.md §9 のリスク対策
「マス+駒ハイブリッドトークン化への後退」) ができなくなるため。
出力の形 `(B, N, 81, 2)` は両者同じなので、損失・マスク・一致率の計算は共有している。

### 2. 欲求ヘッド・自由項ヘッドは第1層を分解して計算する

DESIGN.md §3(3) は $u_{i,a} = [h_i \| E_{pos}[dst(a)] \| \rho(a)]$ をMLPに通す形だが、
$40 \times 81 \times 2 = 6480$ 通り全てに対して $u_{i,a}$ を実体化すると
1局面あたり 6480×321 の入力になって回らない。第1層は線形なので

$$W_1 u_{i,a} = \underbrace{W_1^{(h)} h_i}_{駒ごと} + \underbrace{W_1^{(m)} E_{move}[a]}_{手ごと}$$

と分解し、`(B, N, H)` と `(162, H)` をブロードキャストで足す。中間テンソルは
`(B, N, 162, H)` で、$H=32$ ならバッチ256で 200MB 程度。
**数式は変えていない** (等価な計算順序の入れ替え)。

$E_{pos}[dst]$ と $\rho$ は分けず162通りの手を1つの埋め込みにした
(線形層に入る直前で連結するのと等価)。

### 3. $L_{desire}$ は「実際に指された手の (移動先, 成り)」で評価する

DESIGN.md §4 の $L_{desire} = \sum_{i,k}\mathrm{BCE}(d^{(k)}_i(a_t), y^{(k)}_i)$ は
指し手 $a_t$ を固定している。一方、欲求ラベル $y_i$ は「局面 $t$ における駒 $i$」の
ものであって手には依存しない (`data/labels.py`)。

そこで **$a_t$ の (移動先, 成り) 成分を全駒に当てて** $d_i(a_t)$ を取り出し、
教師と突き合わせる。6軸は足し、駒は有効トークンで平均する。

「動いていない駒の欲求を、動いた駒の移動先で評価する」のは一見奇妙だが、
DESIGN.md の式がそう書いてあり、ラベル側も局面単位なので整合している。

### 4. $L_g$ は合法手だけで平均する

$L_g = \frac{1}{|\mathcal{A}|}\sum_{i,a} g_i(a)^2$ の $|\mathcal{A}|$ を
**合法手数**と読んだ。6480通り全体で平均すると、非合法手の $g$ まで罰する
うえに、局面ごとの合法手数の違いが罰則の実効的な強さに化ける。

### 5. 単調mixingは $\alpha$ を正規化してから混ぜる

DESIGN.md §3(8) は $V = \sum_i \alpha_i V_i + \mathrm{MLP}_b(\bar h)$、
$\alpha_i = |W_{hyp}\bar h|_i \ge 0$。素直に40駒ぶん足すと初期値の時点で
$|V|$ が大きくなりすぎ、**tanh が飽和して勾配が消える** (実測で $V = \pm 1.0$ に
張り付いた)。

$\alpha$ を合計1に正規化してから混ぜることにした。正のスカラーで割るだけなので
$\partial V/\partial V_i \ge 0$ (IGM/単調性) は保たれる。
正規化後の $\alpha$ はそのまま INTERFACE.md §3 の `pieces[].alpha`
(発言力 $\in [0,1]$) として使えるので、Unityへ送る値と学習で使う値が一致する。

回帰テスト: `tests/test_heads.py::test_value_is_monotonic_in_each_piece_value`
(実際に $\partial V/\partial V_i$ を自動微分で取って符号を見る)

### 6. 性格重みに下限 `MIN_WEIGHT = 1e-6` を入れた

$w_i = \mathrm{softplus}(\cdot) > 0$ は数学的には常に正だが、入力が大きく負へ
振れると $\log(1+e^x)$ が **float32 でアンダーフローしてちょうど0**になる
(テストで検出)。0になるとその欲求軸が完全に無視されるうえ、勾配も流れないので
二度と復帰しない。解釈可能性の主張 ($w_i > 0$ だから欲求に対して単調) を
浮動小数点でも守るための下限。

### 7. 欲求説明率は1を超えうる

$$\text{説明率} = \frac{\mathbb{E}\langle w_i,d_i\rangle^2}{\mathbb{E}\,s_{i,a}^2}$$

$s = \langle w,d\rangle + g$ なので、$g$ が $\langle w,d\rangle$ と逆相関すると
分母のほうが小さくなり **100%を超える** (小規模な予備計測で112.9%を観測)。
比であって割合ではないので、これはバグではない。トレードオフ曲線を読むときに
「100%が上限」と誤解しないこと。

## なぜ

- 数式に書いていない実装上の選択 (どの軸で平均するか、どこで正規化するか) が
  結果の解釈を変えてしまうため、後から «どういう定義で測った数字か» を
  辿れるようにする。
- $\alpha$ の正規化と $w$ の下限は、どちらも**放っておくと学習が静かに壊れる**
  類の問題だった (飽和・アンダーフロー)。理由を残さないと元に戻されかねない。

## 影響

- A: Phase 3 で感情 $m_i$ [A] を足すときは `PersonalityWeights(d_mood=...)` に
  次元を渡して連結するだけでよい (個体性格 $\theta^{ind}$ [B] も同様)。
  会議 [D] は `desire` 経路のスコアを初期値 $s^{(0)}$ として使う。
- 他メンバー: 影響なし (INTERFACE.md は変更していない)。
  ただし週6の実データ納品では `desire` / `alpha` がヒューリスティックではなく
  モデル出力になる。値の分布は変わるが、フィールドと値域は同じ。

## 予備計測: トレードオフが実際に出ることの確認 (判定ではない)

4,000局面・1エポック・CPU という縮小条件での $\lambda_g$ 掃引:

| $\lambda_g$ | 一致率 | 欲求説明率 | $\overline{g^2}$ |
|---|---|---|---|
| 0 | 9.57% | 26.0% | 3.7161 |
| 1 | 9.40% | 72.7% | 0.1012 |
| 100 | 6.05% | 99.8% | 0.0000 |

**DESIGN.md が予測した形がそのまま出ている**: $\lambda_g$ を上げると自由項が
抑えられ ($\overline{g^2} \to 0$)、手が欲求で説明できるようになり (説明率 $\to$ 100%)、
その代償に一致率が下がる。$\lambda_g = 1$ 付近では一致率をほとんど落とさずに
説明率が26%→73%まで上がっており、「安く買える解釈可能性」の領域があることを示唆する。

絶対値はデータ量が足りないので意味がない (Phase 2 Gate の判定ではない)。
確認できたのは**機構が設計どおり働いていること**まで。

## 本計測: $\lambda_g$ 掃引 (2026-08-10 追記)

floodgate 2024 の 1,000,069局面・5エポック・batch 512 (WSL + RTX 3050) で
縮退版3点を計測した。

```
uv run python scripts/sweep_lambda_g.py --shard-dir data/shards/2024 \
    --epochs 5 --batch-size 512 --device cuda
```

| $\lambda_g$ | 一致率 | 欲求説明率 | $\overline{g^2}$ |
|---|---|---|---|
| 0 | 34.38% | 19.0% | 13.63 |
| 0.01 | 33.92% | 39.8% | 1.98 |
| 0.1 | **33.96%** | **91.5%** | 0.22 |

**トレードオフはほぼ「タダ」だった**。$\lambda_g = 0.1$ で説明率19%→91.5%まで
上がるのに、一致率の低下は -0.42pt しかない。予備計測が示唆した「安く買える
解釈可能性」の領域が本計測でも成立し、しかも予想以上に安い。
また desire ヘッド ($\lambda_g=0$) の一致率 34.38% は Gate1 の plain ヘッド
(34.27%) と同水準で、**欲求分解の構造化自体に棋力のコストがない**ことも確認できた。

論文の主図としては曲線が平坦すぎて面白くない可能性がある。$\lambda_g = 1.0$ 以上の
点を足すと右端 (説明率 ~100% で一致率が崩れる領域) が見えるはず。継続タスク。

生データ: `checkpoints/lambda_g_sweep.json` / ログ: `checkpoints/lambda_g_sweep.log` /
重み: `checkpoints/desire_lambda{0.0,0.01,0.1}.pt`

### 捨て駒検出の定性確認: 仮説は支持されなかった (要再検討)

`scripts/analyze_free_term.py` で検証局面2,000件を測った。「損な交換」の簡易
プロキシ = 指したあと相手が移動先を取り返せて、動かした駒の価値 > 取った駒の価値。

| 測り方 | $\lambda_g$=0 | 0.01 | 0.1 | ランダム合法手 |
|---|---|---|---|---|
| \|g\|最大の合法手が損な交換である率 | 22.3% | 35.5% | 33.2% | 37.3% |
| 教師手の平均\|g\| — 捨て駒/通常手の比 | 0.63倍 | 0.67倍 | 0.77倍 | — |

**どちらの測り方でも3チェックポイント一貫して仮説と逆**: \|g\| が大きい手は
損な交換になり**にくく**、実際に指された捨て駒の \|g\| は通常手より**小さい**。
「\|自由項\| が捨て駒検出器になる」(DESIGN.md §4a) は、このプロキシでは
支持されない。

ただし棄却と断定する前に測定側の限界を疑うべき:

1. プロキシが粗い。取り返しの存在しか見ておらず SEE (静的交換評価) ではない。
   紐付きの駒交換 (取り返されても続きで得する手) を「損」に誤分類している
   疑いがある (教師手の23%が「損な交換」判定になるのは明らかに多すぎる)
2. 蒸留のみのモデルは捨て駒の「意図」を学ぶ機会がない。価値ヘッドが弱い
   (val value_loss ~1.15) 段階では、g は捨て駒より「欲求6軸で表現できない
   定跡的な手」を背負っている可能性がある

継続タスク: SEE ベースの捨て駒判定に差し替えて再測定。それでも逆なら
DESIGN.md §4a の該当主張を修正する。
